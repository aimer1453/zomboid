## 一、决策记录（已拍板 ✅）

### 决策 1：背包系统 —— 维持重量制，不回归方格制 ✅

**结论（2026-08-05 项目方确认）**：背包按之前确定的**重量制**方案继续（负重上限 50kg + 16 格物品位），GDD 初版中的 8×10 方格制**不实施**。

| 维度 | 最终采用（重量制） |
|------|-------------------|
| 容量模型 | 负重 50kg + 16 格物品位 |
| 数据结构 | `Dictionary item_id→count` + 总负重 |
| UI | 4×4 网格（色块 + 稀有度边框） |
| 已接入功能 | 稀有度边框 / 右键食用 / 全部拿走 / 装备三槽 |

**给 Codex 的指令**：背包系统**已定稿**，按现有 `InventoryBackpack` 重量制实现扩展，禁止改为方格制。后续可做 UI 增强（如更大网格视觉、拖拽整理），但底层重量模型不变。

## 二、其余冲突记录（保留供参考）

### 冲突 2：视角 —— 2.5D 等轴 vs 当前 2D 俯视

- GDD：2.5D 等轴视角（《紫色晶石》风格）
- 现状：2D 俯视 + 占位色块（TileMapLayer 网格）
- **判断**：非代码冲突，是美术阶段差异。网格坐标逻辑（`grid_pos`/`world_to_grid`）可完全复用，等轴只是渲染层替换。
- **给 Codex 的指令**：本轮不做视角迁移；占位色块阶段保持俯视。

---

### 冲突 3：回合制模型 —— AP 池 vs 单动作回合制

- GDD 文档示例：按 AP 降序逐个行动（`yield` 等待输入）
- 现状：单动作回合制（走一步/打一次=回合结束）+ 敌人**并行行动**（同帧启动）
- **判断**：现状是文档模型的**工程优化版**（动画更连贯、异步节奏等价），已通过 P1-1 类型化重构和全流程回归。**保留现状**。
- **给 Codex 的指令**：TurnManager 只增不改，禁止按 GDD 示例重写。

---

### 冲突 4：主地图 —— "固定大地图" vs 程序化城市

- GDD：固定城市废墟，关键地点位置不变
- 现状：程序化生成但**布局固定**（3×3 建筑地块 + 道路 + 安全屋，`main_map.gd` 常量布局）
- **判断**：语义一致（关键地点位置确定），无需改动。副本内部分结构随机，符合 GDD。
